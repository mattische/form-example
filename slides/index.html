Pseudoklasser och element

  • Ett "tillstånd" hos ett element, t ex focus, valid, read-only, hover m.fl
  • Skrivs med ett kolon: selector:tillstånd { ... }
  • "Aktivceras" av användaren eller webbläsaren, inte av vår HTML
  • css för att växla mellan klasser
  • Pseudoelement har två kolon: ::placeholder, ::after

Exemplet med länkar, a

a { color: blue; }
a:hover { color: red; }
a:visited { color: purple; }
a:active { color: green; }

Prova: håll musen här, klicka

Samma element, olika utseende beroende på tillstånd.

Några exempel på pseudoklasser

  • :hover, :focus-visible: aktiveras av muspekar och/eller tangentbordet
  • :required, :read-only: är egenskaper hos fältet
  • :user-invalid / :user-valid: efter att användaren fyllt i
  • :first-child, :nth-child(): position bland siblings/syskon

Pseudoelement

Pseudoklass = är ett "tillstånd" t ex :hover.
Pseudoelement = är "en del" av ett element t e x ::after.

.newRecord::after { content: " NY SKIVA!"; }

html: <span class="newRecord"></span> nu skrivs följande ut på sidan (via CSS)NY SKIVA!

Texten finns alltså inte skriven i html-koden.
css lägger till den.

Exempel pseudoklasser för validering av formulär

  • .input:user-invalid: när användaren fyllt i ett fält med ogiltigt värde (och lämnat det)
  • .input:user-valid: när användaren fyllt i ett giltigt värde
  • .input:user-invalid ~ .hint: väljer hjälptexten efter ett ogiltigt fält

Finns också t ex :invalid, :valid som till skillnad från prefixet:user-"aktiveras" invalid direkt, dvs innan användaren gjort något

några till exempel för formulär: focus, read-only

  • :focus-visible: när elementet har/får fokus till exempel när man tabbar dit
  • :read-only: användaren kan inte ändra. Anväönd attributet readonly
  • ::placeholder: exempeltexten i ett tomt fält. Placeholder finns så länge fältet är tomt och försvinner när man skriver

Hållbarhet på webben

  • Danny van Kooten (2020): 1 kB mindre i en fil på 2 miljoner sajter ≈ 2950 kg CO2 per månad
  • Räkning: 0,5 kWh/GB × 0,295 kg CO2/kWh. Grov uppskattning, poängen är resonemanget
  • Pihkola m.fl. (2018): mindre energi per GB, men mer användning. Rebound-effekt
  • Vår webshop: 12 miniatyrer ≈ 0,5 MB mot 12 fullstora bilder ≈ 28,6 MB (ca 58 gånger)
  • stripe.js ≈ 324 kB mot vår egen kod ≈ 22 kB. Säkerhet kostar vikt
  • VI KAN PÅVERKA: tex med bildstorlekar, färre anrop till externa tjänster/bibliotek, använda färre moduler/paket

AI, datacenter och hållbarhet

  • Enligt IEA (2025): datacenter ca 1,5 % av världens el 2024 (415 TWh), väntas mer än dubblas till 2030
  • Enligt Google (2025): en median Gemini-fråga ≈ 0,24 Wh, 0,03 g CO2e och 0,26 mL vatten
  • Mäter inte: träning, hårdvarutillverkning, nätverk, din enhet. Företagets egen mätning
  • Billigare per fråga, men fler frågor. Samma rebound som ovan
  • VI KAN PÅVERKA: kalla inte AI vid varje tangenttryck, korta prompts, återanvänd svar, behövs AI alls?
