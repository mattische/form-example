Pseudoklasser: vad är det?

  • Ett tillstånd hos ett element: fokus, ogiltigt, skrivskyddat ...
  • Skrivs med ett kolon: selector:tillstånd { ... }
  • Ändras av användaren eller webbläsaren, inte av vår HTML
  • Gör att vi slipper JavaScript för att växla klasser
  • Pseudoelement har två kolon: ::placeholder, ::after

Första exemplet: länkar

a { color: blue; }
a:hover { color: red; }
a:visited { color: purple; }
a:active { color: green; }

Prova: håll musen här, klicka

Samma element, olika utseende beroende på tillstånd.

Vanliga pseudoklasser

  • :hover, :focus-visible: musen och tangentbordet
  • :required, :read-only: egenskaper hos fältet
  • :user-invalid / :user-valid: efter att användaren fyllt i
  • :has(): välj en förälder utifrån vad den innehåller
  • :first-child, :nth-child(): position bland syskon

Pseudoelement

Pseudoklass = ett tillstånd (:hover). Pseudoelement = en del av ett element (::after).

.ny::after { content: " NYTT!"; }

HTML: <span class="ny">Ny skiva</span> ger Ny skiva

Texten finns inte i HTML:en. CSS lägger till den.

Exempel: validering

  • .input:user-invalid: gäller när användaren fyllt i ett fält med ogiltigt värde, och lämnat det
  • .input:user-valid: gäller när användaren fyllt i ett giltigt värde
  • :user-invalid i stället för :invalid, som gäller redan när sidan laddas, innan användaren gjort något
  • .input:user-invalid ~ .hint: väljer hjälptexten efter ett ogiltigt fält
  • I vårt exempel visas det med ram, bakgrund och text, inte bara färg

några till exempel: fokus, read-only

  • :focus-visible: gäller när elementet har fokus och webbläsaren anser att fokus ska synas, till exempel när man tabbar dit
  • :read-only: gäller ett fält som användaren inte kan ändra, det vill säga med attributet readonly (e-postfältet från Stripe)
  • ::placeholder: väljer exempeltexten i ett tomt fält. Den finns så länge fältet är tomt och försvinner när man skriver

Stripe: lite tips/fakt från dokumentationen

  • Det finns ett testkort som alltid lyckas: 4242 4242 4242 4242
  • Och ett som alltid nekas: 4000 0000 0000 0002
  • Ange alltid datum i framtiden (t ex 12/34), valfri CVC funkar

Hållbarhet på webben

  • Danny van Kooten (2020): 1 kB mindre i en fil på 2 miljoner sajter ≈ 2950 kg CO2 per månad
  • Räkning: 0,5 kWh/GB × 0,295 kg CO2/kWh. Grov uppskattning, poängen är resonemanget
  • Pihkola m.fl. (2018): mindre energi per GB, men mer användning. Rebound-effekt
  • Vår webshop: 12 miniatyrer ≈ 0,5 MB mot 12 fullstora bilder ≈ 28,6 MB (ca 58 gånger)
  • stripe.js ≈ 324 kB mot vår egen kod ≈ 22 kB. Säkerhet kostar vikt
  • Du påverkar: rätt bildstorlek, loading="lazy", färre anrop, färre beroenden

AI, datacenter och hållbarhet

  • Enligt IEA (2025): datacenter ca 1,5 % av världens el 2024 (415 TWh), väntas mer än dubblas till 2030
  • Enligt Google (2025): en median Gemini-fråga ≈ 0,24 Wh, 0,03 g CO2e och 0,26 mL vatten
  • Mäter inte: träning, hårdvarutillverkning, nätverk, din enhet. Företagets egen mätning
  • Billigare per fråga, men fler frågor. Samma rebound som ovan
  • Du påverkar: kalla inte AI vid varje tangenttryck, korta prompts, återanvänd svar, behövs AI alls?
