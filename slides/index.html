Testkort: 4242 4242 4242 4242, datum 12/34, valfri CVC

Varför ingen egen kortfält?

Säkerhet, ansvar och regler (PCI).

Stripe tar över kortfälten. Vi kodar inte själva.

Betalningar kräver en server. Den ligger i Lager-API:t.

Flödet med Stripe

  • Klienten ber Lager-API:t skapa en checkout-session
  • API:t svarar med clientSecret
  • Stripe visar sitt formulär i #checkout
  • Tillbaka med ?session_id=...
  • session-status ger e-post och payment_id
  • Då visas vårt eget formulär

Stripes formulär är en förebild

  • Ett fält per rad, tydliga etiketter
  • Fel visas direkt vid fältet
  • Autofyll fungerar
  • Prova ett nekat kort: 4000 0000 0000 0002

Ett användarvänligt formulär

  • Synlig label vid varje fält
  • Rätt type: email, tel, text
  • autocomplete och required
  • pattern (reguljärt uttryck) för format
  • placeholder bara som exempel, aldrig i stället för label
  • Hjälptext om formatet

Jämför med ett dåligt formulär

CSS-pseudoklasser

  • :user-invalid / :user-valid (inte :invalid)
  • :focus-visible, :required, :read-only
  • ::placeholder
  • Inte bara färg: tjockare ram och bakgrund

Se style/forms.css

Från formulär till order

  • submit + event.preventDefault()
  • new FormData(form) och formData.get("...")
  • POST /orders med e-post och payment_id
  • readonly följer med i FormData, disabled gör det inte

När det går fel

  • fetch kastar bara fel vid nätverksfel
  • Kontrollera response.ok
  • try/catch och visa felet på sidan
  • Validering i klienten är inte säkerhet. Servern validerar också.
